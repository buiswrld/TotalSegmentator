New research observations

6 items

Findings the full dataset surfaces that the 57/38-subject subsets couldn't show — either because there wasn't enough data, or because the underlying analysis exists in the pipeline's code but was never run/kept for the paper's numbers. These are additions worth discussing, not corrections to existing text.

Prostate: a new near-total CT failure mode

37 masks, 0% accept rate, mean IoU 0.77. Sex-specific and low-prevalence, so the 57-subject val set likely never had enough prostate masks to register as a distinct structure with "sufficient support" — it isn't mentioned anywhere in the paper's per-structure discussion. Worth adding alongside portal/splenic vein as a named worst-performer, and worth a sentence on why: it's plausibly a small-organ-in-a-large-pelvis boundary-tolerance case (§1's size-bias argument), compounded by low training prevalence.

Pelvic bone family becomes evaluable

368 masks, transfer AUC 0.859 — didn't have enough masks to appear as its own leave-one-family-out row in the paper's 13-family table at all. Now the second-best-transferring family after muscle.

Every CT structure now has "sufficient support"

108/117 structures met the ≥25-masks/≥5-minority-examples bar in the paper; all 117/117 do now. The within-organ AUC analysis (§4.3) and leave-one-organ-out transfer (§4.5) both gained real additional structures (66→93 organs with sufficient data) rather than just tighter confidence intervals on the same ones.

The threshold-uniformity claim is a pooled average — it doesn't hold family-by-family

The paper checks threshold-invariance only in aggregate (§4.4: AUC flat within 0.010–0.017 across the whole dataset). ablations.py has always been able to break this down per anatomical family, but that output — threshold_sweep_by_family.csv and its volatility summary — was never generated for the paper's subset at all. At full scale it reveals real heterogeneity the pooled number hides:

FamilyAUC range across thresholdsAccept-rate swing
reproductive0.262 (0.43–0.69)0–70%

The reproductive family (spleen, prostate, uterus — organs with the fewest examples) is nearly 8× more threshold-sensitive than vertebrae. A reader who takes §4.4's flat pooled curve at face value could reasonably conclude the cutoff choice doesn't matter for any anatomy — it matters a great deal for some. Worth a paragraph and a supplementary table; this doesn't contradict the paper's claim, it scopes it correctly.

Small-sample within-organ AUC is unreliable in both directions

Comparing all 66 structures common to both the paper's within-organ AUC table and the full rerun:

Several structures that looked below chance in the paper's subset (duodenum at 0.247 is worse than a coin flip) turn out to be genuinely, if weakly, predictive once there's more data — that's small-sample noise, not a real model failure the paper should have flagged. The reverse also happens: structures with suspiciously perfect subset AUCs (rib_right_7 at 0.997) regress toward more realistic values with more data. Practical implication for the revision: any per-organ AUC number computed on well under ~25–30 masks should be treated as a rough estimate, not a precise one — worth stating as an explicit caveat next to Table 1/3, since the paper doesn't currently flag this instability itself.

Reproducibility

Everything above is reproducible by a teammate from the committed repo state, with one external dependency. Exact commit hashes and file paths below.

One thing you can't skip: the official train/val/test split labels (meta.csv) aren't committed to the repo — only the derived, already-scored metrics are. You need the original dataset directories (or just their meta.csv files) mounted locally to re-derive the split assignment. Everything downstream of that is a plain, deterministic rerun of committed code against committed data.
